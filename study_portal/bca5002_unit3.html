Unit III: JDBC (Java Database Connectivity)

JDBC Architecture, 4 Driver Types, 5 Steps to Connect, Statement vs PreparedStatement, and ResultSet Navigation.

⚡ The 5 Essential Steps in JDBC
  1. Load the Driver Class:
    Class.forName("com.mysql.cj.jdbc.Driver");
  2. Establish Connection:
    Connection con = DriverManager.getConnection("jdbc:mysql://localhost:3306/db", "user", "password");
  3. Create Statement Object:
    Statement stmt = con.createStatement(); (or con.prepareStatement(sql))
  4. Execute SQL Query:
    ResultSet rs = stmt.executeQuery("SELECT * FROM students"); (or executeUpdate() for DML)
  5. Close Resources:
    rs.close(); stmt.close(); con.close(); (releases database locks and memory)
1. The 4 Types of JDBC Drivers
⭐ CSJMU PYQs: 2025–26, 2023–24, 2022–23, 2021 (The most repeated question in Unit 3!)
Driver Type Common Name Working Mechanism Pros & Cons
Type 1 JDBC-ODBC Bridge Translates JDBC calls into ODBC calls, which then talk to database native driver Cons: Slow performance, requires ODBC installed on client machine (Platform dependent). Obsolete.
Type 2 Native-API Driver Uses Java native interface (JNI) to call vendor-specific C/C++ client client libraries (e.g. Oracle OCI) Pros: Faster than Type 1.
Cons: Requires vendor client libraries installed on every client.
Type 3 Network-Protocol Driver (Middleware) Translates JDBC calls into a middleware protocol. The middleware server then translates to database calls Pros: Client needs no database software; supports multiple DBs.
Cons: Maintenance overhead of middleware server.
Type 4 Thin Driver (Native-Protocol) 100% Pure Java. Converts JDBC calls directly into vendor-specific network socket protocol (e.g. MySQL wire protocol) Pros: Best performance, zero client installation, fully platform independent.
Industry standard!
2. Statement vs PreparedStatement
⭐ CSJMU PYQs: 2024–25, 2021, 2019 (Why use PreparedStatement? Code example)
Feature Statement PreparedStatement CallableStatement
Compilation Compiled and parsed by database every time it executes Pre-compiled once by database; reused with new parameters Used to execute pre-compiled Stored Procedures
Performance Slow for repeated queries Much Faster for parameterized repeated execution High performance on database server
Parameters No parameters (requires string concatenation) Supports positional parameters using ? (placeholders) Supports IN and OUT parameters
Security Vulnerable to SQL Injection Immune to SQL Injection (escapes special characters) Secure
PreparedStatementDemo.java (PYQ Solved) 
import java.sql.*;

public class PreparedStatementDemo {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/college_db";
        String user = "root";
        String pass = "password123";

        // SQL Query with positional placeholders (?)
        String query = "INSERT INTO Student(roll_no, name, marks) VALUES(?, ?, ?)";

        try (Connection con = DriverManager.getConnection(url, user, pass);
             PreparedStatement pstmt = con.prepareStatement(query)) {

            // Setting parameter values (1-indexed!)
            pstmt.setInt(1, 101);
            pstmt.setString(2, "Rahul Verma");
            pstmt.setDouble(3, 88.5);

            int rowsAffected = pstmt.executeUpdate();
            System.out.println("Rows successfully inserted: " + rowsAffected);

        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}
3. ResultSet & ResultSetMetaData

A ResultSet maintains a cursor pointing to its current row of data. Initially the cursor is positioned before the first row.

  • rs.next(): Moves cursor forward one row. Returns false when no more rows exist.
  • rs.getInt(column) / rs.getString(column): Retrieves column value by 1-based index or column name.
  • ResultSetMetaData: Provides metadata about the ResultSet itself (e.g., rsmd.getColumnCount(), rsmd.getColumnName(i), rsmd.getColumnTypeName(i)).
