1. Servlet Lifecycle & Web Container
⭐ CSJMU PYQs: 2025–26, 2024–25, 2023–24, 2022–23, 2021 (The core servlet question!)

A Servlet is a server-side Java component managed by a Web Container (like Apache Tomcat). The container manages the servlet through three lifecycle methods:

Servlet Lifecycle: Load & init() [Once] → service() [Multi-threaded] → destroy() [Once]
The 3 Lifecycle Methods Explained:
  1. init(ServletConfig config): Executed once when the servlet instance is loaded into server memory. Initializes resources like DB connection pools.
  2. service(HttpServletRequest req, HttpServletResponse res): Executed for every client request. The container spawns a new lightweight thread for each request and dispatches to doGet() or doPost() based on HTTP method.
  3. destroy(): Executed once when the servlet is taken out of service (server shutdown or undeployment). Releases connections and cleans up.
2. doGet() vs doPost()
⭐ CSJMU PYQs: 2025–26, 2023–24 (High-Frequency 5-mark question)
Feature doGet() (HTTP GET) doPost() (HTTP POST)
Data Transmission Parameters appended directly to the URL string (?name=value&age=20) Parameters encapsulated inside the HTTP request body
Data Size Limit Limited by browser URL length (~2048 characters) Unlimited (Supports file uploads and large payloads)
Security & Privacy Insecure: Sensitive data (passwords) visible in address bar and server access logs Secure: Data is hidden in payload body and can be encrypted via HTTPS
Caching & Bookmarks Can be cached, bookmarked, and stored in browser history Cannot be bookmarked or cached
Idempotence Idempotent (multiple identical requests produce same result) Non-idempotent (re-submitting can duplicate an order/charge)
3. The 4 Session Tracking Techniques
⭐ CSJMU PYQs: 2025–26, 2024–25, 2023–24, 2021, 2019 (Why needed and explain all 4 methods)

Why Needed: HTTP is a stateless protocol; each request is treated as independent with no memory of prior requests. Session tracking maintains conversational state across multiple page requests (e.g., maintaining an e-commerce shopping cart).

Technique How it Works Pros & Cons
1. Cookies Small text files sent by server and stored on client's browser (Cookie c = new Cookie("user", "Rahul"); response.addCookie(c);) Pros: Lightweight, persists across sessions.
Cons: Can be disabled by user; limited to 4KB.
2. HttpSession Server creates a session object with a unique JSESSIONID stored in memory. Accessed via HttpSession session = request.getSession(); Pros: Stores complex Java objects securely on server.
Cons: Consumes server memory for many concurrent users.
3. URL Rewriting Appends session identifier to every link URL (e.g. page.jsp;jsessionid=A3F982) using response.encodeURL(url) Pros: Works even if client browser has disabled cookies!
Cons: All hyperlinks must be encoded.
4. Hidden Form Fields Embedded invisible inputs inside HTML forms: <input type="hidden" name="user" value="Rahul"> Pros: Simple.
Cons: Only works with form submissions; breaks on normal link navigation.
GreetingServlet.java (PYQ Solved) 
import java.io.*;
import javax.servlet.*;
import javax.servlet.http.*;

public class GreetingServlet extends HttpServlet {
    public void doGet(HttpServletRequest request, HttpServletResponse response) 
            throws ServletException, IOException {
        
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();

        // Retrieve form parameter
        String username = request.getParameter("uname");
        if (username == null || username.trim().isEmpty()) {
            username = "Guest";
        }

        out.println("<html><body>");
        out.println("<h2>Welcome to BCA Portal, " + username + "!</h2>");
        out.println("<p>Server Time: " + new java.util.Date() + "</p>");
        out.println("</body></html>");
    }
}
