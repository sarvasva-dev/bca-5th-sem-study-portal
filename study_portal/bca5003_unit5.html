1. Transport Layer: TCP vs UDP
⭐ CSJMU PYQs: 2024–25, 2023–24, 2021, 2018 (Asked almost every year for 5–10 marks)
⚡ Essential Pass Content
Feature TCP (Transmission Control Protocol) UDP (User Datagram Protocol)
Connection Type Connection-Oriented (3-way handshake before transfer) Connectionless (fire-and-forget; no pre-established session)
Reliability Guaranteed; uses positive ACKs, timeouts, and retransmissions Unreliable; best-effort delivery; packets can be lost, reordered, or duplicated
Header Size Variable: 20 to 60 bytes Fixed: 8 bytes (low overhead)
Flow & Congestion Control Yes; dynamic sliding window and congestion window None; applications must regulate their own transmission rate
Real Applications Web browsing (HTTP/HTTPS), File transfer (FTP), Email (SMTP), SSH Live video streaming, VoIP (WhatsApp calls), Online gaming, DNS queries, DHCP
2. TCP 3-Way Handshake Mechanism
⭐ CSJMU PYQs: 2025–26, 2022, 2019 (Complete diagram and SYN/ACK sequence numbering)

Before transmitting any user payload data, TCP establishes a synchronized virtual connection using three control segments:

The TCP 3-Way Handshake Connection Establishment Sequence
The 3 Handshake Steps Explained:
  1. Step 1 (SYN): Client sends a segment with the SYN control flag set and chooses a random Initial Sequence Number (ISN) $x$.
  2. Step 2 (SYN + ACK): Server allocates connection buffers, picks its own sequence number $y$, and sends an acknowledgment acknowledging $x$: Ack = x + 1.
  3. Step 3 (ACK): Client confirms receipt of server's sequence number: Ack = y + 1. Data transfer can now commence bidirectionally.
3. Application Layer Protocols
⭐ CSJMU PYQs: 2024–25, 2022, 2017 (DNS hierarchy, SMTP vs POP3/IMAP, and port numbers)
Protocol Default Port Transport Protocol Core Function
DNS (Domain Name System) Port 53 UDP (queries) / TCP (zone transfers) Resolves human-readable domain names (e.g. google.com) to 32-bit IP addresses.
SMTP (Simple Mail Transfer) Port 25 / 587 TCP Push Protocol: Uploads outgoing emails from client to server, and transfers emails between mail servers.
POP3 (Post Office Protocol 3) Port 110 TCP Pull Protocol: Downloads emails to local client and deletes them from server by default (single-device).
IMAP (Internet Message Access) Port 143 TCP Pull Protocol: Synchronizes emails and folders across multiple devices (mobile, laptop) while keeping copies on server.
HTTP / HTTPS Port 80 / 443 TCP Transfers web pages; HTTPS uses SSL/TLS encryption for end-to-end security.
4. Cryptography: Symmetric vs Asymmetric & Digital Signatures
⭐ CSJMU PYQs: 2025–26, 2023–24, 2020, 2016 (Symmetric vs Asymmetric, RSA algorithm, and Digital Signatures)
⚡ Essential Pass Content
Feature Symmetric Key Cryptography (Secret Key) Asymmetric Key Cryptography (Public Key)
Number of Keys One single secret key shared by both sender and receiver Two mathematically linked keys: Public Key (open) + Private Key (kept secret)
Encryption / Decryption Same key encrypts and decrypts: $C = E_K(P), P = D_K(C)$ Public key encrypts $\to$ Only matching Private key can decrypt
Key Distribution Major problem: How to securely share the secret key over an insecure channel? Solved: Public key can be freely distributed to the world
Speed Extremely fast; ideal for encrypting large gigabytes of bulk data Computationally slow (heavy modular exponentiation of prime numbers)
Standard Algorithms DES, 3DES, AES (Advanced Encryption Standard) RSA (Rivest-Shamir-Adleman), Diffie-Hellman, ECC
Digital Signatures & Non-Repudiation:

A Digital Signature provides authenticity, integrity, and non-repudiation:

  1. Signing: The sender generates a cryptographic hash of the document and encrypts the hash using the Sender's Private Key.
  2. Verification: The receiver decrypts the signature using the Sender's Public Key and compares it with the hash of the received document.
  3. If the hashes match, it guarantees that: (1) The document was not altered in transit, and (2) The sender cannot deny having sent it (Non-repudiation)!
