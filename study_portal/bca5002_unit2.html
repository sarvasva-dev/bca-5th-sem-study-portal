1. Applet Architecture & Lifecycle
⭐ CSJMU PYQs: 2024–25, 2022, 2019, 2016 (Applet lifecycle diagram, paint vs repaint, param tag)
🎯 Learning Objectives:
  • Understand how an Applet runs inside a web browser/appletviewer.
  • Trace the 5 core lifecycle methods: init(), start(), paint(), stop(), destroy().
  • Distinguish between local applets and remote applets.
⚡ Essential Pass Content

An Applet is a special type of Java program embedded within an HTML webpage that executes client-side inside a Java-enabled web browser or appletviewer.

Complete 5-Stage Java Applet Lifecycle Flow
The 5 Lifecycle Methods:
  1. init(): Invoked once when the applet is first loaded into memory. Used to initialize variables, load images, and set up GUI components.
  2. start(): Invoked immediately after init(), and again every time the user returns to the browser tab. Restarts animation or processing.
  3. paint(Graphics g): Called automatically when the applet output must be redrawn. Uses the Graphics context to draw strings, shapes, and images.
  4. stop(): Invoked whenever the user navigates away from the web page or minimizes the browser. Suspends background threads to save CPU cycles.
  5. destroy(): Invoked once before the applet is completely unloaded from memory. Cleans up non-memory resources.
2. AWT Layout Managers: Flow, Border & Grid
⭐ CSJMU PYQs: 2024–25, 2021, 2018 (FlowLayout vs BorderLayout vs GridLayout comparison)
⚡ Essential Pass Content
Layout Manager Default Placement Strategy Default For
FlowLayout Arranges components in a directional flow, left-to-right in lines. When a row is full, it wraps to the next line. Preserves component's preferred size. Panel and Applet
BorderLayout Divides container into 5 discrete geographic zones: NORTH, SOUTH, EAST, WEST, and CENTER. Components stretch to fill their region. Frame and Dialog
GridLayout Lays out components in a rigid two-dimensional rectangular grid of equal-sized rows and columns ($R \times C$). Every cell is identical in size. Calculators, Keypads
3. Event Delegation Model
⭐ CSJMU PYQs: 2025–26, 2023–24, 2020 (Event Source, Event Listener, and Adapter Classes)
⚡ Essential Pass Content

Java GUI event handling is governed by the Event Delegation Model, where an Event Source delegates the task of processing an event to one or more registered Event Listeners.

The 3 Participants in Event Delegation:
  1. Event Source: The GUI component that generates the event when the user interacts with it (e.g. Button, TextField).
  2. Event Object: Encapsulates all event state information (e.g. ActionEvent, MouseEvent, KeyEvent).
  3. Event Listener: An interface containing callback methods. A listener registers with a source using addXxxListener() (e.g. button.addActionListener(this)).
Why Do We Need Adapter Classes?
Java listener interfaces often have multiple abstract methods. For example, WindowListener mandates implementing 7 methods (`windowOpened`, `windowClosing`, `windowClosed`, `windowIconified`, `windowDeiconified`, `windowActivated`, `windowDeactivated`). If you only want to close the window, you would be forced to write 6 empty dummy methods!
An Adapter Class (e.g. WindowAdapter) implements the interface with empty bodies. You simply extend WindowAdapter and override only the single method you need!
