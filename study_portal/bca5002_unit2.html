1. Applet Lifecycle Methods
⭐ CSJMU PYQs: 2025–26, 2024–25, 2023–24, 2022–23, 2021, 2015 (Applet lifecycle is asked in almost every paper!)

An Applet does not have a main() method; its execution is controlled by the browser/appletviewer through five lifecycle methods in java.applet.Applet:

Applet Lifecycle: Born (init) → Running (start/paint) → Idle (stop) → Dead (destroy)
The 5 Lifecycle Methods Explained:
  1. public void init(): Called exactly once when the applet is loaded. Used to initialize variables, load fonts/images, and add GUI components.
  2. public void start(): Called after init() and each time the browser returns to the web page. Starts or resumes execution.
  3. public void paint(Graphics g): Called whenever the applet display area needs to be redrawn (e.g. using g.drawString() or g.drawRect()).
  4. public void stop(): Called when the user leaves the HTML page or minimizes the browser. Suspends running animations or audio.
  5. public void destroy(): Called exactly once when the applet is permanently terminated and removed from memory.
ColorChangeApplet.java (PYQ Solved) 
import java.applet.Applet;
import java.awt.*;
import java.awt.event.*;

/* <applet code="ColorChangeApplet.class" width="300" height="200"></applet> */
public class ColorChangeApplet extends Applet implements ActionListener {
    Button bRed, bGreen, bBlue;

    public void init() {
        bRed = new Button("Red");
        bGreen = new Button("Green");
        bBlue = new Button("Blue");

        add(bRed); add(bGreen); add(bBlue);

        bRed.addActionListener(this);
        bGreen.addActionListener(this);
        bBlue.addActionListener(this);
    }

    public void actionPerformed(ActionEvent e) {
        if (e.getSource() == bRed) setBackground(Color.RED);
        else if (e.getSource() == bGreen) setBackground(Color.GREEN);
        else if (e.getSource() == bBlue) setBackground(Color.BLUE);
        repaint();
    }
}
2. Layout Managers & Defaults
⭐ CSJMU PYQs: 2024–25, 2023–24, 2022–23 (What is default layout of Applet, Frame, Panel?)
Default Layouts (Must Memorize for 3-mark question):
• Default for Applet & Panel = FlowLayout
• Default for Frame & Dialog = BorderLayout
Layout Manager Arrangement Behavior Key Characteristic
FlowLayout Arranges components sequentially in a line, left to right, wrapping to the next line if width is exceeded Default for Panel and Applet; honors component's preferred size
BorderLayout Divides container into 5 regions: NORTH, SOUTH, EAST, WEST, and CENTER Default for Frame; CENTER expands to occupy remaining space
GridLayout Divides container into a rectangular grid of equal-sized rectangular cells ($r$ rows $\times$ $c$ columns) Every component is forced to have identical width and height
CardLayout Treats each component as a card in a deck where only one card is visible at any given moment Ideal for tabbed wizards / screens
3. Delegation Event Model & Adapter Classes
⭐ CSJMU PYQs: 2025–26, 2024–25, 2023–24, 2021 (Event, Source, Listener, and Adapter classes)
  • Event Source: The GUI component that generates the event when the user interacts with it (e.g., clicking a Button).
  • Event Object: Encapsulates details about what happened (e.g. ActionEvent, MouseEvent).
  • Event Listener: An interface containing callback methods (e.g., ActionListener with actionPerformed()). The listener registers with the source via addActionListener().
  • Adapter Classes: Abstract classes (like MouseAdapter, WindowAdapter) that implement listener interfaces with empty method bodies. You only need to override the specific methods you care about, saving massive boilerplate code!
