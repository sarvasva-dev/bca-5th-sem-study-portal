1. Platform Independence & JVM Architecture
⭐ CSJMU PYQs: 2025–26, 2024–25, 2021 (Why is Java platform independent? JDK vs JRE vs JVM)
🎯 Learning Objectives:
  • Explain the "Write Once, Run Anywhere" (WORA) philosophy.
  • Distinguish between JDK, JRE, and JVM.
  • Identify the major components of JVM internal memory.
⚡ Essential Pass Content

"Write Once, Run Anywhere" (WORA): When Java source code (.java) is compiled with javac, it is not converted directly into machine-dependent CPU machine code. Instead, it generates intermediate, architecture-neutral Bytecode (.class). This bytecode is interpreted and executed by the Java Virtual Machine (JVM) installed on any operating system (Windows, Linux, macOS).

The Essential Trio:
• JVM (Java Virtual Machine): The abstract computing machine that loads, verifies, and executes bytecode.
• JRE (Java Runtime Environment): JVM + Core Java Class Libraries (contains everything needed to run Java programs).
• JDK (Java Development Kit): JRE + Development Tools (contains javac compiler, debugger, javadoc).
📚 Full Understanding Track: JVM Memory Structure
JVM Runtime Data Areas:
  • Method Area: Stores class structures, static fields, method bytecodes, and runtime constant pools.
  • Heap Area: The shared runtime data area where all Java objects and arrays are dynamically allocated with new. Managed by the Garbage Collector.
  • JVM Stack: Stores frame stacks for method calls, local variables, and partial evaluation results.
  • PC (Program Counter) Registers: Keeps track of the memory address of the current JVM instruction being executed.
  • Execution Engine: Includes the JIT (Just-In-Time) Compiler (compiles frequently executed hot loops to native code for blazing speed) and Garbage Collector.
2. OOP Pillars: Overloading vs Overriding
⭐ CSJMU PYQs: 2024–25, 2022, 2019 (Polymorphism, Method Overloading vs Overriding)
⚡ Essential Pass Content
Feature Method Overloading (Compile-Time) Method Overriding (Runtime / Dynamic)
Definition Multiple methods in the same class sharing the same name but with different parameter lists Subclass provides a specific implementation of a method already declared in its superclass
Method Signature Must differ in parameter count, types, or order Must be strictly identical (same name, same parameters, compatible return type)
Inheritance Needed? No; occurs within a single class Yes; requires parent-child relationship (extends)
Resolution Time Resolved at Compile Time (Static Binding) Resolved at Runtime using the actual object type (Dynamic Method Dispatch)
3. Exception Handling & Throw vs Throws
⭐ CSJMU PYQs: 2025–26, 2023–24, 2020 (Checked vs Unchecked, throw vs throws difference)
⚡ Essential Pass Content

An Exception is an abnormal condition that arises in a code sequence at runtime, disrupting the normal flow of instructions. Java uses a structured 5-keyword paradigm: try, catch, finally, throw, and throws.

Basis throw Keyword throws Keyword
Purpose Explicitly creates and throws a single exception instance Declares that a method may cause specified exceptions
Location Used inside a method body Appended to the method signature
Syntax throw new ArithmeticException("Divide by zero"); public void readFile() throws IOException { ... }
Quantity Followed by a single exception object instance Can be followed by multiple comma-separated exception classes
The finally Block Guarantee: The finally block always executes regardless of whether an exception is thrown, caught, or unhandled (even if the try block contains a return statement!). It is exclusively reserved for cleanup operations like closing file streams and database connections.
4. Multithreading & Thread Lifecycle
⭐ CSJMU PYQs: 2024–25, 2022, 2019, 2016 (Thread lifecycle SVG, extends Thread vs implements Runnable)
⚡ Essential Pass Content

A Thread is a lightweight sub-process—the smallest unit of processing. Multithreading allows concurrent execution of two or more parts of a program for maximum CPU utilization.

Feature extends Thread implements Runnable (Preferred)
Inheritance Flexibility Class cannot extend any other class (Java lacks multiple class inheritance) Class is free to extend another base class while implementing Runnable
OOP Design Tightly couples thread code with the thread execution mechanism Separates the job (task) from the runner (Thread instance)
Resource Sharing Each thread object is unique; difficult to share state Multiple threads can share a single Runnable instance

Java Multithreading Example 
class MyRunnableTask implements Runnable {
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(Thread.currentThread().getName() + " count: " + i);
            try {
                Thread.sleep(500); // 500 ms pause
            } catch (InterruptedException e) {
                System.out.println("Thread interrupted: " + e.getMessage());
            }
        }
    }
}

public class ThreadDemo {
    public static void main(String[] args) {
        MyRunnableTask task = new MyRunnableTask();
        Thread t1 = new Thread(task, "Worker-1");
        Thread t2 = new Thread(task, "Worker-2");
        t1.start(); // Moves thread from NEW to RUNNABLE
        t2.start();
    }
}
