1. Java Platform Independence & JVM
⭐ CSJMU PYQs: 2025–26, 2024–25, 2021 (Why is Java platform independent? JDK vs JRE vs JVM)

"Write Once, Run Anywhere" (WORA): Java source code (.java) is compiled by javac into an intermediate architecture-neutral Bytecode (.class), which is executed by the Java Virtual Machine (JVM) on any operating system.

JDK vs JRE vs JVM:
• JVM (Java Virtual Machine): The runtime engine that loads, verifies, and executes bytecode.
• JRE (Java Runtime Environment): JVM + Core Java Class Libraries (for running programs).
• JDK (Java Development Kit): JRE + Development Tools (javac, jar, debugger).
2. Method Overloading vs Overriding
⭐ CSJMU PYQs: 2025–26, 2023–24, 2022–23 (Compile-time vs Runtime Polymorphism)
Feature Method Overloading Method Overriding
Definition Multiple methods in same class with same name but different parameter lists Subclass provides specific implementation of a method already defined in superclass
Polymorphism Type Compile-time (Static binding) Runtime (Dynamic method dispatch)
Method Signature Must differ in parameters (type, number, sequence) Must have identical name, return type, and parameters
Inheritance Needed? No Yes (IS-A relationship required)
Abstract Class vs Interface:
• Abstract Class: Can have both abstract and non-abstract (concrete) methods, instance variables, and constructors. Supports single inheritance only.
• Interface: Contract with 100% abstract methods (prior to Java 8), variables are implicitly public static final. A class can implement multiple interfaces, solving the Diamond Problem!
3. Exception Handling Hierarchy & Keywords
⭐ CSJMU PYQs: 2025–26, 2024–25, 2021, 2019 (Checked vs Unchecked, throw vs throws, final vs finally vs finalize)
Comparison Entity 1 Entity 2
Checked vs Unchecked Checked: Checked at compile-time (e.g. IOException, SQLException). Must be handled via try-catch or declared with throws. Unchecked: Occur at runtime under RuntimeException (e.g. NullPointerException, ArithmeticException). Not forced at compile-time.
throw vs throws throw: Used inside a method to explicitly throw a single exception instance (e.g. throw new ArithmeticException("Divide by 0");). throws: Used in method signature to declare that the method may throw exceptions (e.g. void readFile() throws IOException).
final vs finally vs finalize() final: Keyword applied to variables (constant), methods (prevent override), classes (prevent inheritance). finally: Block following try-catch that always executes (for cleanup like closing files/sockets).
finalize(): Garbage collector cleanup method before reclaiming object.
4. Multithreading & Thread Lifecycle
⭐ CSJMU PYQs: 2025–26, 2024–25, 2023–24, 2022–23, 2021 (The #1 repeated long question!)
Thread Lifecycle States:
  1. NEW: Thread created using new MyThread(), not yet started.
  2. RUNNABLE: start() method called. Thread is ready or running on CPU.
  3. BLOCKED / WAITING: Waiting for a monitor lock or waiting indefinitely for another thread (via wait() or join()).
  4. TIMED_WAITING: Sleeping for a specified duration (via Thread.sleep(ms)).
  5. TERMINATED: run() method has completed execution or unhandled exception occurred.
ThreadCreationDemo.java (Runnable Interface) 
// Preferred approach: Implementing Runnable interface
class TaskRunner implements Runnable {
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println("Child Thread count: " + i);
            try {
                Thread.sleep(500); // 500 ms delay
            } catch (InterruptedException e) {
                System.out.println(e);
            }
        }
    }
}

public class Main {
    public static void main(String[] args) {
        TaskRunner task = new TaskRunner();
        Thread t1 = new Thread(task); // Pass runnable target
        t1.start(); // Moves thread from NEW to RUNNABLE
        System.out.println("Main thread continues executing...");
    }
}
Thread Synchronization:
When multiple threads access shared mutable data simultaneously, race conditions occur. The synchronized keyword locks the object's monitor so only one thread can execute the critical block at a time.
